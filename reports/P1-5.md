# P1-5: Webhooks cannot reach internal addresses

- Branch: `night/P1-5` · Instance: main (tmux session "main") · Date: 2026-11-12
- Status: done

## Done

Before: an agent's webhook URL (the doorbell, `server/agent/events.ts`) only had
to be http(s). The server POSTed to it from inside the network, so it could be
pointed at `http://127.0.0.1:9000` (PHP-FPM), the database, the LAN, or
`169.254.169.254` (cloud metadata), and `fetch` followed redirects (a public
URL could bounce the POST inward). Classic SSRF.

- `server/agent/netguard.ts` (new):
  - `isInternalIp()`: loopback, RFC 1918, link-local, CGNAT `100.64/10`,
    multicast, reserved and documentation ranges, IPv6 `::1`, ULA `fc00::/7`,
    link-local, multicast; IPv6 forms that embed an IPv4 (`::ffff:127.0.0.1`,
    `::127.0.0.1`, NAT64 `64:ff9b::`, 6to4 `2002::`) are checked as that IPv4.
    Odd IPv4 spellings (`2130706433`, `0x7f.1`, `017700000001`) are normalised
    by the URL parser and caught.
  - `assertPublicWebhook()`: http(s) only, no `user:pass@`, `localhost` and
    `*.localhost` refused, host names resolved (all A/AAAA records: one internal
    record is enough to refuse).
  - `ATRIUM_WEBHOOK_ALLOW`: host names (`hooks.lan`), wildcards (`*.lan`), IPs
    and CIDRs (`10.8.0.0/16`, `fd00::/8`).
- Checked **when the URL is saved** (`updateSettings`, error `invalid_input`
  shown in Settings > Agents; a name that does not resolve yet is accepted) and
  **before every POST** (DNS may have changed): a blocked target is recorded as
  the doorbell error and the owner notified once, no retry loop.
- The doorbell no longer follows redirects (`redirect: 'manual'`); a 3xx is
  recorded as an error ("set the final URL").

## Questions for the human

- CGNAT `100.64.0.0/10` is blocked by default. **NetBird/Tailscale addresses are
  in that range** (gallium/oxygen are `100.122.x.x`): if an agent's webhook runs
  on another NetBird machine, add it to `ATRIUM_WEBHOOK_ALLOW` (for example
  `100.122.210.35`).
