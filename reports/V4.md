## Done

### Messages (V4-2..V4-7, ADR 0010, now "accepted")

- `services/gmessages/` (Go 1.27, libgm `go.mau.fi/mautrix-gmessages` v0.2610.0):
  QR pairing (QR renewed every 30 s, 6 times), Google-account pairing
  (cookies, then the emoji to tap), conversations, messages, send, mark
  read, media, start a conversation by number. Events go to Bun as an SSE
  stream. `Authorization: Bearer <secret>` (constant-time compare) on every
  route but `/healthz`; 1 MB body limit; user ids and numbers checked. The
  sidecar stores nothing: Bun keeps the pairing session sealed
  (AES-256-GCM with the instance secret, user id as associated data, so a
  session copied to another user does not open). `GMESSAGES_FAKE=1`: an
  in-memory phone (pairs itself after 3 s, answers every text).
- `server/agent/messages/`: tables `atrium_msg_*`, sync on pairing and on
  every event, every message kept (phone deletions ignored), the "sending"
  placeholder replaced by the phone's echo, pictures kept in the database,
  names from Contacts (last 9 digits match), events `message.received`,
  `message.sent`, `message.failed`, `messages.phone_offline` (codes never in
  events), owner routes, demo data for alice and bob.
- Agent tools (area `messages`, declared by `apps/messages/appinfo/info.xml`):
  `messages_conversation_list`, `messages_message_list`, `messages_search`,
  `messages_mark_read` (write), `messages_send` (send: approval by default,
  payload frozen, summary "Text "…" to Léa"). One-time codes (bank, 2FA,
  `G-123456`…) are replaced by "[one-time code hidden from agents]" and not
  findable by their digits, unless the owner allows that agent (Messages >
  Phone & agents).
- `apps/messages/`: React app (link my phone with the QR drawn in the page by
  `qrcode-generator`, Google-account tab, "Good to know" limits, conversation
  list with unread dots, thread with day groups and runs, links as links,
  read-only senders, SMS segment counter, offline/demo banners, settings),
  animations (bubbles grow from their side, mine fly up, QR scan line, emoji
  breathes, linked check pops). Minimal PHP app for the menu entry.
- Header search has a "Messages" group; the morning digest and the Today
  card list texts waiting for a reply (never one-time codes).
- Dev compose runs the fake phone; `deploy/wavium` gets a `messages` profile
  (read-only, no capabilities, 256 MB) and `install.sh` writes the secret.

### Security check

Found and fixed:

1. **Stored XSS in the note preview** (`apps/notes/web/markdown.ts`): the
   bare-URL linker ran over the whole HTML, so a URL inside an image's alt
   text inserted `<a href="...">` inside the attribute, closing its quotes;
   `![x https://e.co/a/onerror=alert(1)// b](https://img/a.png)` gave an
   `onerror` handler. Notes can be shared, so another user could be hit.
   Now URLs are linked in text only. 14 payload tests, checked to fail on
   the old code.
2. **Mail compose paste cleaning** (`RichText.tsx`): `java\tscript:`,
   entities, `data:`/`vbscript:` links, `<svg>`, `<form>`, `<base>`,
   `<meta>`… now dropped; only http(s)/mailto/tel/relative links stay.
3. **Files the web server should not serve**: TypeScript sources, lockfiles
   and `node_modules` of every UI, `services/`, `reports/` (all were 200 on
   the dev stack). Now 403/404; `dist/` still served. Route tests added.
4. **Headers**: `Permissions-Policy` on every response (camera, mic, payment,
   USB… off; location only for Wavium itself, the weather widget uses it);
   the shell page gets `Content-Security-Policy: frame-ancestors 'self';
   base-uri 'self'; object-src 'none'; form-action 'self'` and
   `Cross-Origin-Opener-Policy: same-origin`. A full script CSP was not
   added: the shell has an inline import map and theme script (would need
   hashes; left to do).
5. **Test tooling**: `bun audit` found 12 advisories (4 critical) in vitest
   3.2.4 / happy-dom 18 / tinypool, test-only. Updated to vitest 4.1.12 and
   happy-dom 21.0.4 (both > 2 weeks old); `bun audit` clean, all web tests
   pass. `apps/notes/web` and `apps/messages/web`: clean.

Checked and fine: every SQL interpolation in `server/` is a table name or a
placeholder; owner routes need a session plus `OCS-APIRequest` on writes and
refuse cross-site; a user cannot read another user's texts or correct
another user's mail (tests); the sidecar is not published and needs the
secret; webhooks and the new test button keep the private-address guard
(also when DNS changes after saving) and never follow redirects; the mail
reader shows mail HTML in a sandboxed frame without scripts and with a CSP.

New code written with the same care: correction hints reach the AI prompt
only as fixed sentences matched by a strict pattern (no text from mails);
media from texts is served with a safe type, `nosniff` and a sandbox CSP;
event payloads never carry codes.

### Agents (V4-8, V4-9, V4-11)

- Settings > Agents > Doorbell > **Test**: one signed POST (`X-Atrium-Test: 1`),
  same guards as the real doorbell, answer in plain words, one per 5 s.
- Tokens: `whoami` now names the token used; Bun records time, address
  (behind a private proxy: the last `X-Forwarded-For` entry, the one Caddy
  wrote) and client per token (`atrium_agent_token_use`, one write per 30 s);
  **Revoke** is one click.
- **Quiet hours** per agent (may cross midnight, owner's time zone): no
  doorbell and no approval ping, unless an event is urgent "now"; held rings
  go out when the window ends; the digest and Today card count the agent
  requests waiting.
