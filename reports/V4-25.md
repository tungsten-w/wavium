# V4-25: the twice-daily mail brief was failing silently under cron

- Branch: `night/V4-25` · Instance: Claude (interactive session) · Date: 2026-11-23
- Status: done

## Done

`brief.sh` runs the `claude-mail` agent twice a day from cron (`30 7` and `30 18`).
Cron gives a process almost no `PATH`, and `claude` lives in
`/home/oxygen/.npm-global/bin`, which is not on it. The 18:30 pass of 2026-11-23
died with `timeout: failed to run command 'claude': No such file or directory`
(rc=127). Nothing surfaced the failure: `brief.md` still held the 17:01 report,
so the brief looked merely stale rather than broken.

The script lives outside this repo and is not under version control
(`/home/oxygen/claude-mail/` is not a git work tree), so the fix is there and
this report is the record of it. The previous version is kept as
`brief.sh.bak` next to it.

Changes to `/home/oxygen/claude-mail/brief.sh`:

- an explicit `PATH` (`/home/oxygen/.npm-global/bin:/usr/local/bin:/usr/bin:/bin`)
  exported at the top, which covers every command the script needs, not just
  `claude` (`python3`, `timeout`, `mktemp`, `date`, `wc`);
- `CLAUDE_BIN`, resolved from `command -v claude` with an absolute fallback and
  overridable from the environment, so the script can be tested without touching
  the real mailbox;
- the binary is checked with `-x` **before** the agent is invoked: a missing
  `claude` now exits 127 with a message instead of burning the 900 s timeout;
- failures are loud: `fail()` writes one line to `brief.log`, writes
  `brief.status` with the reason plus the effective `PATH` and `CLAUDE_BIN`, and
  prints to stderr so cron can mail it. `brief.md` is still only overwritten on
  success, so the last good report is never destroyed;
- the two silent failure modes the old script shared with the loud one are now
  distinguished: `rc=124` (timeout) and `rc=0` with an empty report.

`HOME` is exported with a default, since the agent runs on the Claude
subscription and reads its configuration and credentials from it.

## Tested

The real brief was **not** run: it would reach the owner's live Wavium instance
and real mailbox, which rule A1 rules out. What was verified instead:

- `bash -n brief.sh` — clean (this is also what `make lint` checks for the
  repo's shell scripts).
- The bug reproduced and then shown fixed:
  `env -i sh -c 'command -v claude'` → not found (the 18:30 failure);
  `env -i sh -c 'export PATH=<script PATH>; command -v claude'` →
  `/home/oxygen/.npm-global/bin/claude`. `python3`, `timeout` and `mktemp` all
  resolve under the same `PATH`.
- Sandbox harness (a copy of the script with `D` pointed at a temp directory, a
  stub sorter and a stub agent), run under `env -i` to imitate cron:
  - success path → rc=0, `brief.md` rewritten with the dated marker,
    `brief.status` = `ok (1 lignes)`;
  - `CLAUDE_BIN=/nonexistent/claude` → rc=127, stderr message, `brief.status`
    carries the reason, the `PATH` and the binary, and `brief.md` is left
    untouched.

Proof that it works end to end on the real mailbox will be the 07:30 cron pass:
`brief.status` should read `ok` and `brief.md` carry today's date.
