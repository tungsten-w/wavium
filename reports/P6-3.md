# P6-3: backup and restore in one command

- Branch: `night/P6-3` · Instance: A (phase-0 session) · Date: 2026-11-13
- Status: done

## Done

- `deploy/backup.sh backup|verify|restore`, used by `make backup` and
  `make restore BACKUP=backups/<date>` on the dev stack, and usable for
  production by setting `ATRIUM_COMPOSE`, `ATRIUM_APP_SERVICE=app`,
  `ATRIUM_STOP_SERVICES="app cron"` (documented at the top of the script).
- A backup = `db.dump` (`pg_dump -Fc`, whole DB: Nextcloud, Atrium mail copy,
  agent tables) + `files.tar.gz` (`config/config.php`, `data/`, `custom_apps/`)
  + `MANIFEST` (date, version, sizes, sha256). Taken in maintenance mode; a
  trap turns maintenance off again on any failure.
- Restore refuses without `--yes` and refuses a backup whose checksums do not
  match, before touching anything. It stops the services that hold DB
  connections (Bun keeps a pool), restores the files, then makes the DB role of
  the restored `config.php` exist with its password (Nextcloud creates its own
  role with a random password at install, so this is what lets a backup land
  on a fresh install), recreates the DB owned by that role (PostgreSQL ≥ 15
  gives no CREATE on `public` to others), `pg_restore`, starts, refreshes the
  data fingerprint so sync clients rescan.
- `make test-backup` = `deploy/dev/backup-test.sh`, end-to-end test.

## Tested

`make test-backup` on this branch's own dev stack (:8097): **23 passed, 0
failed**: backup + manifest + verify; maintenance off afterwards; changes made
after the backup (new file, deleted demo file, new user); a corrupted copy is
refused and leaves the instance alone; after restore: the deleted file is
back, the new file and new user are gone, mail account, calendar event and
agent layer are fine, not in maintenance; then `make reset` (fresh install,
new random DB role password) and restore again: same 7 checks pass.
