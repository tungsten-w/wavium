# P2-4: Mail triage on the provider layer (instead of tollgate), `mail-v2` kept

- Branch: `night/P2-4` · Instance: sodium-7a (tmux session "main") · Date: 2026-11-13
- Status: done

## Done

- **Design**: PHP keeps everything it already does well: the queue, the IMAP
  fetch (one login per run), stored bodies, its € caps, the backoff states, the
  `mail_triage` tables, classify on arrival, the reclassify button. Only the AI
  call changes: instead of tollgate's `/v1/decisions`, `TriageService` posts the
  same `{input, questions}` to the Bun server, which answers in the **same
  decisions shape**. `summarize()`, the stored `raw` JSON, `mail.received` events
  and every reader of `mail_triage` are unchanged (`mail-v2` kept).
- **Bun** `server/ai/triage.ts`: questions.json → one forced tool `classify`
  (enums for choices and levels, 0..1 numbers for predicates, `<name>_confidence`
  for choices; built from the file, so a new question needs no code). The answer
  is checked (unknown choice, missing or out-of-range = invalid; lenient on
  form: case, percent, booleans, JSON strings); one retry on a bad answer. The
  system prompt says the mail is data, not instructions (prompt injection).
- **Bun** `server/ai/triage-route.ts`: `POST /agent/v1/internal/ai/triage`,
  internal only (X-Atrium-Internal HMAC, timing-safe; checked in
  `server/agent/ai.ts`, the one wiring point the P2-1 acceptance test allows).
  As the **account owner**: their Settings > AI provider (else the instance
  one), task `triage` → small model (P2-5), call through the **budget** (P2-3,
  usage in `atrium_ai_usage` per user, pauses on errors). Statuses: 200; 409 no
  AI; 402 budget with `until`; 401 key refused; 429 / 503 with `until`; 422
  bad model answer.
- **PHP** `TriageService`: app config `triage_backend` = `ai` | `tollgate`;
  unset = `tollgate` when a tollgate token exists (**existing installs keep
  working**), else `ai`. New result `not_configured` (no AI: wait 10 min);
  pauses use the AI's `until`; a bad model answer counts one attempt on that
  mail (parked after 5), pipeline problems never do; cost = (input + output
  tokens) × the existing price setting; the model shown on the status page is
  "<provider label> · <model>". Bun server address: `ATRIUM_SERVER_URL`
  (dev compose: `http://web:8080`) or system config `atrium.server_url`.
- **Mock provider**: a request that forces a tool now gets a call to that tool
  with a sample input from the schema (a real model must call it too), so
  triage runs on the dev stack with the mock and no script.
- Mail status page and the stuck-mail alert: texts no longer name tollgate
  ("add an AI in Settings > AI", "the AI refused its key"...).
