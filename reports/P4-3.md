# P4-3: Tasks gaps (repeating tasks, manual order, sharing)

- Branch: `night/P4-3` · Instance: session B (main session, Claude) · Date: 2026-11-13
- Status: done

## Done

React Tasks app (`apps/tasks/web`), no PHP change. Pure logic in `recur.ts`,
CalDAV sharing in `sharing.ts`, dialog in `Share.tsx`.

- **Repeating tasks**: "Repeat" in the detail (none / every day / week /
  month / year; a custom RRULE from another app is shown and kept). Ticking a
  repeating task that has a date does not close it: its due and start dates
  move to the next occurrence after today (whole days, so the time of day
  survives a DST change; month ends kept: 31 Jan → 28 Feb → 31 Mar), and a
  toast says "Done. Next: …". Without a date, or with a custom rule, it is
  completed as before. A repeat icon shows in the list.
- **Manual order**: in a list, drag a task onto another to put it before it
  (siblings only), or "Move up / Move down" in the task menu; stored as
  `X-APPLE-SORT-ORDER` (what Apple Reminders, Thunderbird and upstream Tasks
  use), only the tasks whose value changes are written. Collections (All,
  Today…) keep their date order.
- **Sharing a list**: "Share" in the list menu: who has it (can view / can
  edit), add a person or a group found by name (Nextcloud's sharee search),
  change access, stop sharing. CalDAV sharing (`oc:share` / `oc:invite`), so
  phones see the share.
- **Bug found and fixed**: two quick edits of one task (e.g. a due date, then
  the repeat) overwrote each other (both PUT from the same old copy). Edits
  of one task are now queued, each applied to the version the previous one
  saved. Written down in `docs/lessons.md` (with the happy-dom limit).
