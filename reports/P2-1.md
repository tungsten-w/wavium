# P2-1: AI provider layer (`server/ai/`)

- Branch: `night/P2-1` · Instance: dev (agent team) · Date: 2026-11-12
- Status: done

## Done

One provider-neutral interface in TypeScript, not wired anywhere yet (P2-2..P2-5 do that).

### Public API (`server/ai/index.ts`)

- `createProvider(config, {fetch})` returns an `AiProvider` (a `MockProvider` for `kind: 'mock'`). Kinds: `anthropic`, `openai`, `mistral`, `openai-compatible`, `ollama`, `mock`. `KINDS` holds the default base URLs and whether a key is needed.
- `AiProvider`: `complete(req)`, `stream(req)` (text and tool_call events, then exactly one `done`), `listModels()`, `testConnection()` (lists models, spends no tokens).
- `AiRequest`: `model?`, `system?`, `messages`, `tools?`, `toolChoice?` (`auto | none | required | {name}`), `maxTokens?`, `temperature?`, `stop?`, `signal?`.
- `AiResult`: `text`, `toolCalls`, `stopReason`, `usage` (`inputTokens` total, `outputTokens`, `cacheReadTokens?`, `cacheWriteTokens?`, `reported`), `model`, `providerStopReason?`, `raw?`.
- `AiError` codes: `auth`, `budget`, `rate_limit` (with `retryAfter`), `invalid`, `unavailable`.
- Limits: error body 64 KB, JSON answer 8 MB, SSE line/event 1 MB. Redirects: `redirect: 'manual'`.

### Files

- `types.ts`: request / messages (text, tool_call, tool_result blocks) / result / stream events, `AiProvider` (`complete`, `stream`, `listModels`, `testConnection`), `ProviderConfig`.
- `errors.ts`: `AiError` with stable codes `auth` (401/403), `budget` (402, OpenAI 429 `insufficient_quota`, Anthropic 400 "credit balance is too low"), `rate_limit` (429 + `retryAfter` from Retry-After, seconds or date), `invalid` (other 4xx), `unavailable` (408, 5xx, 529, network, timeout). Keys are redacted from every message.
- `sse.ts`: one SSE reader (chunks split mid-line / mid-UTF-8, `\r\n`, `\r`, comments, multi-line data).
- `http.ts`: timeout (idle timeout for streams), caller abort, error mapping.
- `anthropic.ts`: Messages API, tool_use / tool_result blocks, SSE events incl. mid-stream `error`.
- `openai.ts`: Chat Completions for `openai`, `mistral`, `openai-compatible`, `ollama` (tool results become `tool` messages, streamed tool-call pieces, usage chunk).
- `mock.ts`: deterministic mock (echo, queued replies / errors, recorded requests, chunked streaming).
- `index.ts`: `createProvider(config, {fetch})` with config validation, `resolveConfig`, `KINDS` defaults.

### After review (round 2)

- Budget is decided on structured error fields (`insufficient_quota`, Anthropic `billing_error`, `invalid_request_error` + "credit balance is too low"), never on free text: a plain 429 that links to the billing page stays `rate_limit`. `retry-after-ms` wins over `Retry-After`.
- Truncated streams are errors: no `message_stop` (Anthropic), or no `[DONE]` and no `finish_reason` (OpenAI family), or an unterminated tool_use block -> `AiError('unavailable')`.
- `AiRequest.toolChoice`: `'auto' | 'none' | 'required' | {name}` -> Anthropic `{type: auto|none|any|tool}`, OpenAI `auto|none|required|{type:'function', function:{name}}`. Omitted when there are no tools. (No `responseFormat`: Anthropic has no equivalent here; a forced tool call covers P2-4.)
- Anthropic wire: tool_result blocks first in a user turn, empty text blocks dropped, non-object tool input sent as `{}`. OpenAI wire: malformed arguments are echoed back raw, not re-quoted.
- Limits (base URLs will be user-set): error body read up to 64 KB (truncated, still classified by status), JSON answer 8 MB, SSE line/event 1 MB -> `unavailable`. Redirects are not followed (`redirect: 'manual'`, 3xx -> `invalid`).
- Usage: `inputTokens` stays the total; new `cacheReadTokens`, `cacheWriteTokens`, `reported` (false when the server sent none). A failing, timed-out or aborted stream carries `err.usage` (also set on the caller's abort reason when it is an Error).
- Stop reasons: `model_context_window_exceeded` -> `max_tokens`, `pause_turn` and unknown reasons -> `'stop'`, raw value in `AiResult.providerStopReason`.
- Mid-stream error events use the same code mapping as HTTP errors; a streamed tool name is taken once; a model list of an unexpected shape is `unavailable`; the idle timeout only runs while waiting for the server (not while the caller handles an event).

## Questions for the human

- `model` is optional in a request and falls back to the provider's `defaultModel` (the brief listed it as required).
- Anthropic input tokens include cache read/creation tokens (they are billed); the parts are in `cacheReadTokens` / `cacheWriteTokens`.
- OpenAI gets `max_completion_tokens` (newer models refuse `max_tokens`); the other kinds get `max_tokens`. Mistral gets no `stream_options` (it rejects unknown fields and sends usage anyway).
- Malformed tool-call JSON from a model is kept as the raw string in `input`, so the tool's schema validation rejects it clearly instead of the turn failing. Echoed back: `{}` to Anthropic, the raw string to OpenAI.
- A stream that ends with a `finish_reason` but no `[DONE]` is accepted as complete (some compatible servers skip `[DONE]`).
- A caller abort (`signal`) is rethrown as is, not as an `AiError`.
