# P3-2: Calendar + Tasks agent tools, discoverable calendars, `calendar.*` / `task.*` events

- Branch: `night/P3-2` · Instance: main (tmux session "main") · Date: 2026-11-13
- Status: done

## Done

- **Tools** `server/agent/calendar/index.ts` (module registered next to mail), areas
  `calendar` (events) and `tasks` (VTODO), separate grants:
  - `calendar_list`: **discoverable calendars**: own ones, the ones shared with the user
    (`shared_by`, `writable` false for a read-only share) and subscriptions (read-only).
    An agent finds a delegated calendar without knowing its URL (the problem of the
    original agent).
  - `calendar_event_list` (range, default next 7 days, max 366; repeating events expanded;
    text search; one calendar or all), `calendar_event_get` (series + modified
    occurrences, attendees, etag), `calendar_event_create`, `calendar_event_update`
    (only the fields sent; null clears; moving start keeps the duration; etag check),
    `calendar_event_delete` (action delete → approval by default).
  - `task_list` (open / completed / all, due_before, search; due first, undated last),
    `task_get`, `task_create` (subtasks with `parent_id`), `task_update`, `task_complete`,
    `task_delete` (approval).
  - Deletes go to the **calendar trash bin** (30 days), never a hard delete. An approval is
    **void if the event / task changed** after the request (etag kept in the request).
- **PHP** (`apps/calendar`): `Service/AtriumAgentCalendar.php` (simple fields ⇄ iCalendar
  with sabre/vobject, everything through `CalDavBackend`, so phones and DAV clients see the
  changes; checks write access itself since the backend does not: own or read-write share
  only, never a subscription; times in UTC; RRULE validated), `Service/AtriumAgentError.php`,
  `Controller/AtriumAgentController.php` + route `POST /api/atrium-agent` (internal only).
- **Events** `server/agent/calendar/feed.ts`:
  - changes, read from CalDAV's own change log (`calendarchanges`): so **every client**
    counts (web, phone, Thunderbird, agent). `calendar.event.created / updated / deleted`,
    `task.created / updated / completed / deleted`, for the owner **and the users the
    calendar is shared with** (`shared_by` in the data). History is not replayed;
    an edit of a completed task does not repeat `task.completed`.
  - reminders, every minute, only for users with an agent that has read access:
    `calendar.event.starting` (timed events starting within 15 min, `in_minutes`) and
    `task.due` (timed tasks due within 15 min). Each occurrence once. These two are
    **wake hints** (agents with wakes on get a doorbell); the others are not.
- No change to `tools.ts`, `events.ts`, `access.ts`, `schema.ts`; one line in
  `server/agent/index.ts` (`modules: [...]`).

## Left to do

  occurrences are shown read-only).
- Attendees and invitations are read-only (no sending invitations from an agent: that
  would be `send`, needs a decision).
- Times are written in UTC (no VTIMEZONE): fine for clients, but a weekly event created by
  an agent keeps its UTC hour across DST changes. Writing the user's time zone needs a
  VTIMEZONE generator.
- Group shares: events go to directly shared users only (groups not expanded).
- Restoring from the calendar trash bin is not a tool yet (the web UI does it).
