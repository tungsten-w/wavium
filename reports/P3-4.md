# P3-4: Files tools (share = approval)

- Branch: `night/P3-4` · Instance: A · Date: 2026-11-13
- Status: done

## Done

- **Tools** (`server/agent/files/`, area `files`, MCP + REST), items addressed
  by `path` (from the home folder) **or** `file_id`:
  - read: `files_list` (folders first, paging), `files_search` (by name),
    `files_get`, `files_read` (UTF-8 text up to 2 MB, or base64 up to 1 MB),
    `files_share_list`;
  - write: `files_write` (up to 5 MB, text or base64; `etag` refuses a stale
    overwrite, `create_only`, `create_parents`; an overwrite keeps the old
    content as a **version**), `files_mkdir`, `files_move` (never overwrites);
  - delete: `files_delete` → **trash bin**; asks the owner by default; void
    if the item changed after the request; the home folder is refused;
  - share: `files_share` (user, group or public link; read or edit; expiry
    date; note) and `files_unshare`; both ask the owner by default; a share
    request is void if the item is gone. Public links get no password from an
    agent (it would be stored in the approval log): set one in Files.
- **PHP** `apps/files/lib/Controller/AtriumAgentController.php` (internal
  only, routes `/apps/files/api/atrium-agent/*`): acts as the user (volatile
  session user) through `IRootFolder` and the share manager, so quotas,
  versions, trash bin, activity and sharing rules apply as in the web UI.
  Paths are normalised and `..` / control characters refused (`cleanPath`).
- The Files app loads classes from a frozen Composer classmap: the controller
  is added to `autoload_classmap.php` / `autoload_static.php`. Lesson in
  `docs/lessons.md` (a missing controller makes every request 500).
