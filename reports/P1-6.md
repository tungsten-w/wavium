# P1-6: React tests for the shell and Mail (vitest + fake server)

## Done

Before: the React UIs had 3 test files of pure logic (labels, login body,
agents model) and no test that renders a component.

- `core/web/testing/` (new test helpers, no library besides happy-dom):
  - `dom.ts`: installs a happy-dom window as globals (no network: frames,
    scripts, CSS and navigations are not loaded). **Why not
    `// @vitest-environment happy-dom`**: under the Bun runtime that
    `make test-web` uses (`bun --bun vitest`, there is no Node in the image),
    vitest's environment switch breaks module loading ("Cannot find module
    <the test file>"). Checked with a two-line test.
  - `fakeServer.ts`: replaces `fetch` with routes (`on(method, path|regex, handler)`),
    records every call (`calls()`), answers 404 to unknown calls and lists them
    in `unhandled` so a test can assert "no unexpected request";
    `redirectedTo(path)` for fetches that followed a redirect (login).
  - `render.tsx`: `render`, `renderApp` (an app's Component inside `AppCtx`,
    like the shell does), `waitFor`, `getByText`, `getButton`, `getField`,
    `click`, `type` (sets a controlled input the way React notices), `cleanup`.
- `apps/mail/web/mail.ui.test.tsx` (5 tests): the Inbox lists mails with
  sender, **sender address** and subject, unread marked, Curated query
  (`exclude=ads,spam,newsletter,social`); opening a mail loads its body, shows
  it, marks it read (`PUT flags {seen:true}`); writing + Send goes through the
  outbox (`POST /outbox` with the right fields, then `POST /outbox/77`), the
  composer closes; no recipient → nothing sent; Save draft → `POST
  /accounts/1/draft` with the fields.
- `core/web/shell/shell.ui.test.tsx` (5 tests): header apps (no Dashboard; a
  React app replacing Contacts hides it and links to its route; active app has
  `aria-current`); `/` goes to the Dashboard; a classic page opens in an
  iframe with the right `src`; the saved app order (`atrium-app-order`) is
  used; login posts user/password/requesttoken/redirect/rememberme and shows
  "Wrong login or password." when the server sends it back to /login.
- `AGENTS.md` and `core/web/vitest.config.ts`: the DOM-test instructions now
  say how to do it (the old `@vitest-environment` hint did not work).

Found on the way: in a DOM where the "load more" sentinel is visible at once,
the Mail list asks for the next page right away; a fake that ignores
`cursor` makes it loop forever. Real server answers end the loop; the fake
now honours `cursor`.
