# P3-5: Notes tools, then Activity (read only)

- Branch: `night/P3-5` · Instance: A · Date: 2026-11-13
- Status: done

## Done

- **Notes** (`server/agent/notes/`, area `notes`): `notes_note_list`
  (metadata + 200-char excerpt, newest first, `query` over title/category/
  content, `category` includes sub-categories, `favorite`, paging),
  `notes_note_get` (Markdown content sliced with `max_chars`/`offset`),
  `notes_note_create` (title from the first line when absent),
  `notes_note_update` (replace `content`, or `append` a line, `title`,
  `category`, `favorite`; optional `etag` refuses a stale write),
  `notes_note_delete` (asks the owner by default; void if the note was
  edited after the request; the file goes to the **Files trash bin**).
- **Activity** (`server/agent/activity/`, area `activity`, read only):
  `activity_list` (newest first, rendered by the Activity app; `filter`
  all/self/by/app filters, or one object's history; links made absolute;
  cursor = last activity id) and `activity_filters`.
- **PHP** (internal only, `X-Atrium-Internal`):
  `apps/notes/lib/Controller/AtriumAgentController.php` (through
  `NotesService`: notes stay Markdown files, synced by the desktop client and
  the Notes mobile apps) and `apps/activity/lib/Controller/AtriumAgentController.php`
  (the Activity app's `Data::get`, same as its OCS API v2).
- Notes calls run with the user as a volatile session user, so favorites
  (file tags) work and activity says "You ..." instead of "remote account".
- `docs/lessons.md`: dev opcache delay (60 s), session user in internal calls.
