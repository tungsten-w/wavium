## Done

Several agents per user, each with its own permissions, tokens and pause,
already existed (Settings > Agents, P0/P2-6). P2-8 adds the activity part:

- **Agent activity timeline** (`server/agent/timeline.ts`): one list, newest
  first, merging
  - the journal of actions (P3-7), with Undo;
  - approval requests that did not become an action (waiting, rejected,
    expired, cancelled, changed after asking, failed; and executed requests
    from before the journal existed). An executed request shows once, as its
    action, with its `request_id`.
  Ordered by (time, kind, id) descending; the cursor is that triple, so paging
  across the two tables never skips nor repeats an item, even with many items
  in the same second.
- **Owner API**: `GET /agent/v1/owner/activity?agent=&cursor=&limit=`,
  `GET /agent/v1/owner/approvals/<id>` (one request, own requests only), and
  `agent=` on `GET /agent/v1/owner/approvals`.
- **Page Settings > Agent activity** (`/settings/user/agent-activity`,
  `AgentActivity.tsx`): agent filter (in the URL, `?agent=`), what / agent /
  when / state, Undo, and a "Request" button on every line that went through
  an approval. The request opens in a dialog (`?request=`): summary, agent,
  tool, when, state, note, error, the frozen payload, the result; a waiting
  request can be approved or rejected there.
- Each agent card in Settings > Agents has an "Activity" button (the page
  filtered on that agent); the "Recent agent actions" card links to the page.
- Approval notifications (ntfy) now open the request itself
  (`…/agent-activity?request=<id>`) instead of the Agents page.
