# V4-20: a fresh install with install.sh comes up

- Branch: `night/V4-20` · Instance: Claude session · Date: 2026-11-20
- Status: done

The owner asked for the procedure to install the latest Wavium on their
server. Before giving it, the procedure was run as written on a fresh clone
from GitHub (local mode: `WAVIUM_DOMAIN=localhost`, ports 8480/8443, project
`wavium-check`). It failed.

## Done

- **Bug: a fresh install never started.** `install.sh` sets `umask 077` to
  write a private `.env` and kept it for the rest of the run, so `build.sh`
  extracted the code readable by its owner only; in the image the web server
  stopped with `EACCES reading "/opt/atrium/server/index.ts"` and the stack
  never got healthy. `--update` runs (no new `.env`) were not hit, which is
  why it went unnoticed.
  - `install.sh` puts the umask back right after writing `.env`;
  - `build.sh` extracts with `umask 022`, so the image no longer depends on
    the caller's umask.

## Tested

- Before the fix: fresh clone of GitHub `main`, `install.sh --yes` ->
  "The stack did not come up", app log `EACCES reading
  "/opt/atrium/server/index.ts"`.
- After the fix, same fresh install run under `umask 077` on purpose:
  "Wavium answers at https://localhost:8443", `status.php` installed true;
  in a browser the admin logs in, Mail shows the new setup page, the
  username follows the address, no page errors.
- `make lint` (includes `sh -n` on the scripts): pass.
