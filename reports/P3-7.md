# P3-7: undo an agent action from the activity log

- Branch: `night/P3-7` · Instance: main session (Claude) · Date: 2026-11-13
- Status: done

## Done

- **Journal of agent actions** (`server/agent/journal.ts`, table
  `atrium_agent_actions`, created on first use): every tool call whose action
  is not `read` is logged for the grantor, whether it ran at once (`callTool`)
  or after an approval (`Approvals.approve`). One line per action: the
  approval summary when there is one, otherwise a readable label + the main
  field ("New contact: Ada", "New folder: /Projects"). Reads and base tools
  are not logged. A journal failure is logged on the server and never fails
  the action. Kept 30 days.
- **Undo**, built only from the action's input and result (so it is exact):
  | Action | Undo |
  | --- | --- |
  | todo_item_create | todo_item_delete (Daily Todo trash, 7 days) |
  | todo_item_delete / todo_item_postpone | todo_item_restore |
  | todo_item_complete / task_complete | tick/untick back |
  | contacts_contact_create | contacts_contact_delete (copy kept 30 days) |
  | contacts_contact_delete | contacts_contact_restore |
  | notes_note_create | notes_note_delete (Files trash bin) |
  | calendar_event_create / task_create | delete (calendar trash bin) |
  | files_share | files_unshare |
  | files_move (given by path) | move back to that path |
  | files_write with create_only | files_delete (trash bin) |
  | mail_draft_create | mail_draft_delete |
  Everything else is logged with no Undo (edits, overwrites, mail moves,
  send...): Atrium does not know the previous state.
- The inverse runs as the same agent for the same grantor, with no new
  approval (the owner's click is the approval). The row is claimed before the
  call, so two clicks run it once; if the inverse fails the claim is released
  and the error is shown on the row (retry possible); unknown errors give a
  generic message (detail in the server log). The agent gets an
  `action.undone` event.
- **Owner API**: `GET /agent/v1/owner/actions?agent=&cursor=&limit=` (own data
  only, newest first) and `POST /agent/v1/owner/actions/<id>/undo`.
- **UI**: Settings > Agents, card "Recent agent actions"
  (`core/web/shell/settings/AgentActions.tsx`): summary, agent, when, Undo or
  "Undone …", the undo error if any, "Show more".
