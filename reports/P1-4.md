## Done

Before: `server/agent/auth.ts` cached PHP's `whoami` answer for 60 s per set of
auth headers. Only revocations made through the agent layer's own owner API
called `auth.clear()`. A token revoked in Settings > Security (classic page),
with `occ`, by logging out, by a remote wipe or by disabling the user kept
working for up to 60 s.

- Every token, app password and web session is a row of `oc_authtoken`; all of
  those actions delete or change rows there, or set `core/enabled=false` in
  `oc_preferences`. `authFingerprint(db)` reads
  `count(*), max(id), sum(type)` of `authtoken` + the count of disabled users
  (two cheap queries).
- `Auth` re-reads the fingerprint at most **once a second** (shared by all
  concurrent requests) and drops every cached answer when it changes. So a
  revocation from anywhere is seen within ~1 s; with no change, answers are
  still cached 60 s (no extra PHP calls).
- If the fingerprint cannot be read (DB down), answers live 5 s only.
- Any new login also changes the fingerprint and clears the cache: a few extra
  `whoami` calls, accepted (safer than missing a revocation).
