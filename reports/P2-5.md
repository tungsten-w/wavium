## Done

- `server/ai/routing.ts` (new), as agreed with the P2-2 instance (plain map in,
  provider + model out; `server/ai/index.ts` untouched):
  - `resolveRoute(task, {routes, defaultProvider}, providers)` → provider config, model,
    tier, and where each came from (`route` / `provider-default` / `suggested`,
    `route` / `default` / `first`), so the settings page can show it.
  - Tiers: triage = small (cheap), summary, draft, assistant and unknown tasks = large.
  - Model order: route model → provider default (large tasks) → suggested model of the
    kind for the tier → provider default. Suggestions only for kinds with a fixed
    catalogue (Anthropic, OpenAI, Mistral); Ollama / OpenAI-compatible use their default.
  - Errors are `AiError('invalid')` with a settings-ready message: no provider, route or
    default provider that does not exist (never a silent switch to another provider:
    keys and costs differ), no model.
  - `describeRouting()` lists every task's route and the problems apart.
  - `providerForTask(task, cfg, providers, deps)` → `{ route, ai }`, `ai` fills in the model
    (`withModel`); an explicit `req.model` still wins.
- `server/ai/README.md`: "Model per task" section.
