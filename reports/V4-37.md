## What this button does, and what it does not

It runs **the classification pipeline** — Wavium's own triage: the thing that
reads a mail and decides its category, its urgency, whether it needs a reply.
That pipeline otherwise only runs from `TriageJob`, every five minutes. So
turning classification on, adding an AI provider, or choosing a new folder to
classify all looked like nothing had happened, for up to five minutes, with the
status page reading `N waiting for the next run`.

It does **not** run `claude-mail`'s `sort.py` — the external script that files
mail into folders by sender domain. That one is not part of Wavium (it drives
the agent API from the outside, on its own cron). A button for *that* would be
V4-29, "deterministic rules fired on mail arrival, no AI", which is still open
in `TASKS.md`.

On this instance today, with no AI provider configured, pressing it answers:

    Nothing classified: No AI for mail triage: no AI provider is configured.
    Add one in Settings > AI.

That is the point of the button as much as the happy path: it turns a silence
into a sentence.

## Done

**`TriageService::runNow(int $seconds = 20)`** — the same work the cron job
does (`run()`: enqueue, then classify until a deadline), with two differences.

- *It clears `pausedUntil` first.* A pause exists to stop the job hammering an
  AI that keeps failing. A person pressing a button once is not hammering, and
  a failure is exactly when they press it — so without this, the button would
  answer "nothing happened" for up to 30 minutes after a transient error.
  `runClassify` arms the backoff again by itself if this attempt fails too, so
  one press buys one attempt.
- *It refuses while classification is off.* The UI disables the button, but the
  service refuses as well: a stale page must not be able to classify behind a
  human's "no". The refusal happens before the pause is touched.

Its answer always says something: `ran`, a `reason` (`disabled` / `busy`), the
counts, the resulting pipeline `state` and `lastError`.

**`POST /apps/mail/api/triage/run`** → `TriageController::run()`. Admin-only,
like the on/off switch above it and for the same reason: it spends the
instance's AI budget. A press at the wrong moment answers 200 with
`ran: false`, not an error — nothing went wrong, there was just nothing to do.

The deadline is 20 seconds because the call answers an HTTP request and has to
come back inside the web server's timeout. A press therefore classifies a few
mails and says how many are left, rather than trying to drain a backlog of
3401.

**The button**, in `apps/mail/web/Status.tsx`, inside the pipeline card: the
switch and `Run now` now sit together in `.ml-st__controls`, opposite the state
line. Disabled when busy, when classification is off, or when no provider is
configured. Not rendered at all for someone without `canManage`, like the
switch.
