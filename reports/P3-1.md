# P3-1: Daily Todo agent tools and `todo.*` events

- Branch: `night/P3-1` · Instance: main (tmux session "main") · Date: 2026-11-13
- Status: done

## Done

- **Agent tools** `server/agent/todo/index.ts` (new module, area `daily_todo`, registered in
  `startAgentLayer` next to mail):
  - read: `todo_day_get` (a day's items in order, kinds item / routine / task / event,
    done, nesting; divider and blank rows hidden), `todo_overdue`, `todo_trash_list`;
  - write: `todo_item_create` (day slot, `parent_id`, `after_id`), `todo_item_complete`
    (tick / untick), `todo_item_rename`, `todo_item_move` (with its subitems, after a
    sibling or first; the tool computes the full order), `todo_item_postpone` (1-365 days),
    `todo_item_restore` (undo a delete / postpone);
  - delete: `todo_item_delete` (action `delete`, so **approval by default**; the owner sees
    "Delete from Daily Todo (date): "title""). Deleted items stay 7 days in the app trash.
  - Items of today and the two days before are found without a date (the app's editable days).
- **PHP side** (`apps/daily_todo`):
  - `Controller/AtriumAgentController.php` + route `POST /api/atrium-agent`: internal only
    (X-Atrium-Internal, as Mail's), one dispatcher (`op`, `uid`, `agent`, `args`), runs
    `BoardService` as the grantor so every app rule applies; errors mapped to
    404 / 403 / 409 / 400.
  - `Service/AgentEvents.php`: queues `todo.*` events in `atrium_agent_event_queue`
    (grantor = board owner, area `daily_todo`, no wake: Daily Todo has no wake rule yet).
    A no-op when the agent layer's table is absent (checked first, so it can never abort the
    restore transaction on PostgreSQL); never breaks the user action.
  - `BoardService`: one event per change, **from the UI too**: `todo.item.created`,
    `completed`, `uncompleted` (only on a real change), `renamed` (with `old_title`),
    `deleted` / `postponed` (with `trash_id`, `due`), `restored`, `todo.day.reordered`,
    `todo.day.finished`. `data.agent` names the agent when one acted.
    `AgentEvents` is an optional constructor argument: existing callers unchanged.
- Docs: "Atrium agents" section in `apps/daily_todo/AGENTS.md`.

## Tested

- `server/agent/todo/todo.test.ts` (9 tests): views, the move order (subtrees, siblings,
  errors), and the tools through the real call path with a fake PHP bridge: no grant →
  forbidden, read-only → no writes, other grantor refused, arguments sent to PHP, uid =
  grantor and agent named, delete pending approval then executed on approve, delete
  allowed without approval when granted.
- `apps/daily_todo/tests/run-agent.php` (20 checks, real DB, rolled back, run by
  `make test-daily-todo`): every change queues its event in order, event data, no agent
  field from the UI, controller refuses without the internal header, acts as uid, names
  the agent, the agent name does not stick, error codes.
  - It exits 1 on failure: Nextcloud's error handler otherwise logs a fatal error and
    exits **0** (found while writing it; the other `run-*.php` scripts have the same
    weakness: a fatal error there would pass `make test` silently).
- Mutation checks: an event type renamed → `run-agent.php` fails (exit 1);
  `todo_item_delete` action set to `write` → the approval test fails.
- **End to end** on this worktree's own stack (port 8196, demo alice): created an agent with
  daily_todo read + write over the owner API, then over REST with its token: day, create,
  complete, rename, move, delete (→ `pending_approval`), postpone, trash list; then
  `events_since` returned `todo.item.created / completed / renamed / day.reordered /
  item.postponed`, each with `agent: agent-p31-test-bot`.
- `make lint`: OK. `make test`: OK (server 138 pass + 1 skip, web 61, PHPUnit 92 + 68,
  Daily Todo runners incl. `run-agent.php`).
