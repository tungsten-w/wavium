## Done

All in the React Calendar (`apps/calendar/web`), no PHP change; new logic in
`extras.ts`, appointment pages in `Appointments.tsx`.

- **Classic event URLs** (todo.md): `/apps/calendar/edit/<base64>[/<rid>]`
  (what global search builds) and `/<view>/<date>/edit/<mode>/<base64>/<rid>`
  open the event (a given occurrence of a series when `rid` is a timestamp),
  then the address becomes the normal week view. Only calendar object paths
  are accepted (no `..`, nothing outside `/remote.php/dav/calendars/`).
- **Attendees**: the event dialog lists guests with their answer (no answer
  yet / accepted / maybe / declined), invites by email, removes. Saving with
  guests writes `ORGANIZER` (you) and `ATTENDEE …;RSVP=TRUE`; Nextcloud's
  CalDAV scheduling sends the invitations (mail, or straight into a local
  user's calendar). Without guests, both properties go.
- **Answering an invitation**: an event organised by someone else opens
  read-only with "Invitation from …, your answer: …" and Decline / Maybe /
  Accept; only your own `PARTSTAT` changes, on the series and its changed
  occurrences; the server sends the reply.
- **Subscriptions**: "Subscribe to a calendar" (https:// or webcal://, name,
  colour) creates a `cs:subscribed` collection with its `cs:source`;
  Nextcloud's refresh job fetches it. Subscriptions can now be renamed /
  recoloured (Edit) and removed like before.
- **Appointment pages**: an "Appointments" section lists them (length, copy
  the public booking link, delete) and creates one: name, description,
  location, length (15–90 min), target calendar, days and hours of the week,
  public or link-only; uses the Calendar app's `v1/appointment_configs` API.
  The public booking page is still the Calendar app's own page.
