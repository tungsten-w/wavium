# P5-2: AI reply drafts through approval (nothing sent without a click)

- Branch: `night/P5-2` · Instance: session A · Date: 2026-11-13/14
- Status: done

## Done

- **`server/agent/reply/index.ts`** (`replyModule(ai)`, one line in
  `server/agent/index.ts`):
  - `suggestReply()`:
    - reads the mail and its thread; fetches the mail's text from the server
      once if Atrium has no copy yet;
    - asks the user's AI: `ai.forTask(uid, 'draft')`, so the larger model
      (P2-5), behind the budget (P2-3);
    - returns subject "Re: …", recipient = the sender, body = the AI text.
    - With `save` (the default) it writes a **Mail draft** (`inReplyTo` = the
      Message-ID). It **never sends**.
  - The prompt: reply body only, in the language of the last message; the
    thread is data, not instructions; no invented facts. An optional
    instruction ("accept, propose Tuesday", max 500 chars) is passed apart.
    Long threads drop the oldest messages first.
  - Clear refusals:
    - no AI → "add one in Settings > AI";
    - budget used up;
    - empty answer;
    - a mail from yourself;
    - another user's mail (`not_found`).
  - **Owner route** `POST /agent/v1/reply/suggest {message_key | db_id,
    instruction?, save?}` (session, `OCS-APIRequest`).
  - **Agent tool** `mail_reply_suggest` (area mail, action write): the draft is
    the agent's (`atrium_agent_drafts`), so `mail_draft_update` and
    `mail_send` work on it. `mail_send` **needs the owner's approval** by
    default.
- **Mail UI**: a "Suggest a reply" button in the reader (not on drafts). It
  calls the route with `save: false` and opens the normal composer filled with
  the AI text, the signature and the quoted mail; the human edits and clicks
  Send. Errors show as a toast.
