# P3-6: cross-app `search` tool

- Branch: `night/P3-6` · Instance: main session (Claude) · Date: 2026-11-13
- Status: done

## Done

- `server/agent/search/index.ts`: one tool, `search`, that any agent can call
  (area `null`). It takes `query` (2–200 characters), an optional `apps` list
  (mail, files, contacts, notes, calendar, tasks) and `limit` (hits per app,
  default 5, max 20), plus the usual `grantor`.
- It runs the app's **own** read tool for every app the agent can read on that
  grantor (`mail_message_list` text, `files_search`, `contacts_contact_list`,
  `notes_note_list`, `calendar_event_list` six months back and ahead,
  `task_list` status all), in parallel. No new PHP, no index of its own: it sees
  exactly what each app tool sees and nothing more.
- Each hit: `app, kind, id, title, snippet, date` and `open` = the tool call that
  returns the full item (`mail_message_get`, `files_read`/`files_list`,
  `contacts_contact_get`, `notes_note_get`, `calendar_event_get`, `task_get`).
- `skipped` lists the apps with no read access (never queried) or not
  installed; `errors` lists apps that failed (an unknown error shows a generic
  message, the detail goes to the server log) while the others still answer.
- Mail searches the mail tool's default folders (inbox + archive): no spam, no
  trash.
- Wired in `server/agent/index.ts` (`searchModule()`).

## Tested

- `server/agent/search/search.test.ts` (6 tests, stub app tools, real grants
  and `callTool`): no grant → nothing queried; only readable apps queried; hit
  mapping and `open` per app; inputs given to each tool (calendar window, task
  status); `apps` filter, per-app limit; a failing app reported without hiding
  the others and without leaking an internal message; another grantor uses
  their grants; bad inputs refused (`apps: []`, unknown app, limit > 20, query
  < 2 characters after trimming); an app not installed is skipped.
- Mutation check: 7 mutations (access check removed, limit not applied, error
  attributed to the wrong app, calendar window, task status, raw error message,
  "not installed" not reported): each one makes a test fail.
- Real stack (`atrium-p36`, port 8099), REST with an agent token
  (scratchpad script `p36.sh`): seeded a note, contact, file, event and task
  with "Zanzibar", `search` found all of them (and the demo mail "Dîner samedi ?"
  for "Dîner"); every `open` call returned the item; with only notes granted,
  only notes were queried and the rest were in `skipped`; for bob (no grant)
  everything was skipped; `search` shows in MCP `tools/list`.
- `make lint` OK; `make test` OK (server 219 pass / 0 fail, web 72, PHPUnit
  124 + 68, Daily Todo).

## Left to do

- A note is also a Markdown file in `/Notes`, so it shows up twice (notes and
  files). Kept on purpose: the agent can tell by the path, and hiding files
  under `/Notes` would hide real files there.
- No ranking across apps: hits are grouped by app in a fixed order.
- Daily Todo and Activity are not searched (no text search in those tools).
- Side finding, not fixed (other area): `PUT /agent/v1/owner/agents/<uid>/access`
  silently ignores an unknown `preset` (e.g. "none") instead of refusing it.
