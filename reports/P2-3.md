## Done

- `server/ai/budget.ts` (new):
  - `Budget(store, config, {now, onError})` and `budget.wrap(provider, {user, task})`: same
    `AiProvider` interface, so a feature does not change its calls.
  - **Caps** (`BudgetRule`): daily and/or monthly, in USD and/or tokens, scoped by provider
    and/or task (a missing field = all). Checked before each call; a refused call throws
    `BudgetBlocked` (an `AiError` with code `budget`, plus `until` and `reason`:
    `daily_cap`, `monthly_cap` or the pause reason). The provider is not called.
  - **Counter**: every call recorded with tokens (cache read/write apart), cost in USD from a
    price table (`provider:model`, `*:model`, `model`, `provider:*`), `estimated` when the
    server sent no usage (4 chars = 1 token), and the error code for failed calls.
    Failed, aborted and early-stopped streams are counted too.
  - **Automatic pauses**, per user and provider, from `AiError` codes, as in TriageService:
    `budget` → until the next local midnight; `auth` → 1 h; `rate_limit` → Retry-After
    (else backoff); `unavailable` → backoff 30 s, 60 s, 120 s ... 30 min, reset after a
    success; `invalid` and caller aborts → no pause. `resume()` lifts a pause by hand.
  - `summary(user, providers)`: today, month, per provider × task, each cap's use, live pauses
    (for a usage page).
  - Config is a function, read at each call: settings changes (P2-2) apply at once.
  - A bookkeeping failure (database down) never breaks the AI call; it goes to `onError`.
- `server/ai/usage-store.ts` (new): `SqlUsageStore` on Nextcloud's DB (Postgres or sqlite),
  tables `<prefix>atrium_ai_usage` and `<prefix>atrium_ai_pause`, created by the store
  itself (`CREATE TABLE IF NOT EXISTS`), so `server/agent/db.ts` migrations are untouched
  (no clash with P2-2). `MemoryUsageStore` for tests.
- `server/ai/README.md`: "Budgets and usage" section.
- Boundaries agreed with the P2-2 instance: `server/ai/index.ts` not touched; no settings UI
  here.

## Left to do

- Wiring: P2-4 (triage) and the other features wrap their provider with
  `budget.wrap(...)`, `task` = 'triage' / 'summary' / 'draft' / 'assistant'.
- Settings: rules and prices must come from the P2-2 settings (an `AiBudget.tsx` section
  and an owner API for `summary()` / `resume()`), done once P2-2 is merged.
- Provider layer (P2-1) gap found: when a consumer leaves a stream early (`break`), the
  providers do not call `onUsage` (the README says "exactly once"). The wrapper estimates
  the usage in that case; reporting the partial usage in the providers' `finally` would be
  more exact.
- Concurrency: caps are checked before a call; parallel calls can pass a cap by what was in
  flight (no reservation).
- No default price table: prices change, so they come from settings. A model without a
  price costs $0 (token caps still apply).
