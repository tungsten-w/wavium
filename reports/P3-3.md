# P3-3: Contacts tools (simple fields, no raw vCard)

- Branch: `night/P3-3` · Instance: A · Date: 2026-11-13
- Status: done

## Done

- **Tools** (`server/agent/contacts/`, area `contacts`, MCP + REST):
  `contacts_addressbook_list`, `contacts_contact_list` (query over name, org,
  emails and phone digits; paging with `next_cursor`), `contacts_contact_get`,
  `contacts_contact_create`, `contacts_contact_update` (only the fields given;
  `null` clears; emails/phones replace the list; optional `etag` refuses a
  stale write), `contacts_contact_delete`, `contacts_contact_deleted`,
  `contacts_contact_restore`.
- **Fields**: name, given/family name, emails and phones (with a type),
  org, title, note, birthday; addresses read only. `contact_id` =
  `<address book id>/<card uri>`. The raw vCard is never exposed.
- **Delete**: `contacts:delete` is gateable, so by default it asks the owner
  (approval inbox). The request carries the etag: if the contact is edited
  before the owner approves, the request is void. CardDAV has no contacts
  trash, so the agent layer keeps a copy of the vCard for 30 days
  (`atrium_agent_contacts_trash`, created by the module, purged hourly) and
  `contacts_contact_restore` puts it back with the same UID and URI.
- **PHP** (`apps/contacts/lib/Controller/AtriumAgentController.php`, routes
  `/apps/contacts/api/atrium-agent/*`, internal only via `X-Atrium-Internal`):
  everything goes through Nextcloud's `CardDavBackend`, so sync tokens and the
  change log move and phones / DAVx5 / desktop clients see agent edits
  (ADR 0008). Shared address books are listed (`shared_by`); read-only shares
  refuse writes. `AtriumContactMapper` (Sabre VObject) does vCard <-> fields
  and **keeps every property it does not manage** (photo, X-*, addresses...).
  PHP rather than TypeScript here because the writes must go through the DAV
  backend and Sabre already parses vCards robustly.
