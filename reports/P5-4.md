# P5-4: scam hint — display name vs address domain

- Branch: `night/P5-4` · Instance: A (phase-0 session) · Date: 2026-11-13
- Status: done (heuristic part; see "Left to do")

## Done

- `apps/mail/web/spoof.ts`: `senderMismatch(from)` flags a sender whose
  display name claims something its address does not match, without any AI
  or network:
  1. an e-mail address written in the name, on another registrable domain
     (`"support@bank.com" <x@other.net>`);
  2. a domain written in the name (only with a real TLD, so "Dr.Who" is not a
     domain) on another registrable domain (`"paypal.com" <x@evil.example>`);
  3. a brand or institution most often impersonated (PayPal, Amazon, Apple,
     Microsoft, Google, Netflix, DHL, UPS, La Poste, ameli, impôts, CAF,
     French banks, "bank"/"banque"…) when the sender's host does not carry
     one of that brand's domain stems.
  `registrableDomain()` handles common two-level suffixes (co.uk, gouv.fr…).
- Mail list: a red **"Sender mismatch"** chip (tooltip with the reason) next
  to the classifier's chips, incoming mail only (not Sent/Drafts).
- Reader: a red banner under the classification line: "The sender's name
  says “banque”, but the mail comes from example.biz. Check before clicking a
  link or paying anything."
- Works with or without the AI classifier; complements its `suspicious` score.

## Tested

- `apps/mail/web/spoof.test.ts` (18 tests): the three phishing shapes
  (including the demo scam mail), 12 honest senders that must stay clean
  (real brand domains, subdomains, newsletters, "Dr.Who", "Start-ups",
  name = address, empty name), missing sender, banner text.
- `make lint` and `make test-web` (44 tests) pass in Docker.
- Browser check (Playwright, this branch's dev stack on :8095, user alice):
  of the 8 demo inbox mails only the scam sample ("Banque Nationale -
  Sécurité" <alerte@secure-bnq-verif.example.biz>) gets the chip; opening it
  shows the banner; opening an honest mail shows none; no page errors.
