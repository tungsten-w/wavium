# V4-23: Mail — Curated showed an empty Inbox on a freshly connected account

- Branch: `night/V4-23` · Instance: Claude (oxygen) · Date: 2026-11-23
- Status: done

## Why Curated hid everything

Not the preferences, not an inverted test, not the classifier: **the folder had
no local copy yet, and the label list could not say so.**

Mail's two lists read the same local copy of the mailbox. The plain list
(`/api/messages`) answers `MailboxNotCachedException` for a folder that was
never synced, and the client reacts to it — run the initial sync, ask again.
That is what starts the first sync of a folder from the interface. The label
list (`/api/triage/list`, which Curated and the category chips use) ran its
query, found no rows and answered `200 []`. The UI showed "This folder is
empty", and nothing ever asked for the sync, so it stayed that way until the
next background sync.

The production logs say it plainly: at 13:18:13 the account is created, then
`POST /mailboxes/1/sync` answers **428** fourteen times until 13:20:34 (3354
messages to fetch), and every `GET /triage/list` in that window answers
`200`. The first `GET /messages` at 13:20:32 is the moment the person clicked
"All" — and that path is the one that drives the sync.

Mail that has not been classified yet was never the problem in the UI: the SQL
has `t.category IS NULL OR t.category NOT IN (...)` and a left join, verified
against the production database (3354 of 3354 rows match). The **agent layer**
did have the bug, the other way round: `mail.list({curated: true})` required
`t.category IS NOT NULL`, so on an instance with no AI configured it matched
nothing at all.

## Done

- `TriageService::uncachedMailboxIds()`: the user's folders among those asked
  for that have no sync token (same bar as `Mailbox::isCached()`).
- `TriageController::list()` answers `MailboxNotCachedException` as jsend when
  any of them is cold, and names the folders (`mailboxIds`).
- `api.ts`: the retry-and-sync loop became `withInitialSync()`, used by both
  lists; it syncs the folders the server named (every listed folder if the
  server named none, so an older backend still works).
- Agent layer: `curated: true` now means "no category, or a category Curated
  does not hide"; `curated: false` is the exact complement.
- A filter that matches nothing in a folder that does hold mail names the
  filter and offers **See all mail** (one extra request, only in that case).
- The chosen filter is remembered per device (`wavium.mail.filter`), falling
  back to Curated on anything unreadable.
- **Favorites, found while verifying**: it listed the account's `\Flagged`
  folder, which Gmail has and Orange, Free, SFR, iCloud and GreenMail do not —
  so the page was always empty. It now lists starred mail by its flag across
  every folder except Trash and Spam (`flagged=1` on the label list), and says
  "No favorites yet" instead of reading as an empty folder.
- **Account setup errors**: `JsonResponse::fail()` carries the reason, the
  service, the host and the port, and nothing read them — hence the bare
  "HTTP 400" on Gmail. `mailErrorText()` turns it into a sentence, the backend
  adds the mail server's own words (`details`, one line, long tokens stripped),
  and app passwords are sent without the spaces providers print them with.
- v4.2 in `CHANGELOG.md` and Settings > What's new; two lessons in
  `docs/lessons.md`.
