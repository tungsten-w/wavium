# V4-24: tags an agent can actually set

- Branch: `night/V4-24` (on top of `night/V4-26`) · Instance: Claude (interactive session) · Date: 2026-11-23
- Status: done

## Done

`claude-mail` could not sort mail. Its own definition said so — "mettre une
etoile … c'est ton seul droit d'ecriture habituel" — because the mail tools gave
an agent exactly three writes: `seen`, `starred` and `folder`
(`server/agent/mail/write.ts`, `mail_message_update`). It could read the
classifier's answer and star a mail. Nothing else.

It now has five words, the ones asked for: **spam, promo, important, urgent,
etudes**.

### They are not a new store

The classification already holds all five, split the way the questions are
asked: one exclusive `category`, and independent probabilities for urgency,
"needs a reply", "needs an action", "has a deadline" and "suspicious". A tag is
a *reading* of those columns (`server/agent/mail/tags.ts`), so there is one
source of truth (`oc_mail_triage`), nothing to keep in sync, and the agent and
the Mail UI cannot drift apart. No migration, no new table.

Two planes, because the five words are not mutually exclusive — an exam
deadline is `etudes` **and** `urgent`, a fraudulent sale is `promo` **and**
`spam`:

| plane | tags | from |
| --- | --- | --- |
| exclusive | `spam`, `promo`, `etudes` | the `category` column (`promo` is the classifier's `ads`) |
| cumulative | `important`, `urgent` | the predicates and the urgency level |

Derivation, with one threshold — `0.6`, **the number the Mail UI chips have
always used** (`apps/mail/web/index.tsx`, `TriageChips`), not a second one:

- `spam` ⇐ `suspicious >= 0.6`, or category `spam`
- `promo` ⇐ category `ads` · `etudes` ⇐ category `etudes`
- `important` ⇐ any of `needs_reply`, `needs_action`, `has_deadline` `>= 0.6`
- `urgent` ⇐ urgency `today` or `now`

A category the classifier is unsure of (confidence under 0.6) yields no
exclusive tag: better no answer than a wrong one. A mail nothing has classified
has **no** tags — an empty list means "not sorted", never "ordinary mail".

### What an agent can do

`mail_message_tag` — `{message_key, add?, remove?}` → `{message_key, tags}`:

- `area: 'mail'`, `action: 'write'`, so the owner's mail grant governs it. To be
  precise, since the audit got this wrong: `write` is **never** gated by an
  approval — `access.ts` gates `delete`, `send` and `share` only. A tag is
  allowed or off, which is right for something reversible whose last word
  belongs to the owner anyway.
- `prepare`/`execute` rather than `run`, so Settings > Agents > Activity shows
  `Tagged "Dîner samedi ?" as important, urgent` instead of a tool name and a
  message key.
- `remove` takes `important` and `urgent` only. Removing `spam`, `promo` or
  `etudes` would have to invent a category to put in their place; the error says
  to add the right tag instead.
- At most one exclusive tag per call, and the same tag cannot be added and
  removed.
- On a mail with no classification row (no AI configured, or a folder outside
  the pipeline) the agent's answer *becomes* the classification, marked
  `version: 'agent'`, `model: 'tagged-by-agent'`.
- **Refused on a mail the owner classified by hand**: a row with
  `model = 'corrected-by-user'` (what the "Wrong?" button writes, V4-10) answers
  `conflict`. The person whose mail it is has the last word, and no new table was
  needed to say so — the column already recorded it.
- Nothing moves, nothing is deleted. `spam` is a word, not a folder (rule A10).

Reading, the other half of the same thing (this is V4-32, folded in because the
tags come from columns the query already selects): `mail_message_list` rows and
`mail_message_get` carry `tags`, and `mail_message_list` takes
`tag: string | string[]` (every tag given must hold).

`~/.claude/agents/claude-mail.md` was updated too — the tool added to its
allowlist and step 3 of its round rewritten to pose the tags, with the rule that
a mail it cannot judge is left untagged, that a human sender is never tagged
`spam` or `promo`, and that a `conflict` is not to be retried. It is outside the
repo and unversioned; the previous version is `claude-mail.md.bak`.

## Tested

New tests, 22 in all:

- `server/agent/mail/tags.test.ts` (13): the whole truth table — every category,
  each of the three "important" signals, both urgent levels, the planes
  stacking, and the edges of the single threshold (`0.59` vs `0.60`, a `null`
  confidence taken at face value). Plus every refusal, and a round trip asserting
  that what `patchFor` writes is what `tagsOf` then reads back.
- `server/agent/mail/tagwrite.test.ts` (9): the tool through its real
  prepare/execute path — it is a mail write; the journal sentence; tagging a
  classified mail; the two planes on one mail; a mail with no classification
  getting one; **the owner's correction winning**; **nothing reaching the mail
  server** (a bridge that records every call stays empty, and the mail is still
  in its folder); refusals including another user's mail; and the `tag` filter
  finding back what was set.

Two bugs the tests caught while being written, both fixed:

1. `tagsOf` bailed out on a row with no category, so an agent could set
   `important` on an unclassified mail and read back nothing. The early return
   now only means "no row at all".
2. the `tag` filter built every tag's SQL eagerly, so unused clauses still
   appended a parameter and shifted every placeholder (`SQLite query expected 4
   values, received 9`). Clauses are built on demand now.

Checked the tests really test: with the `corrected-by-user` guard removed,
`the owner's own answer is the last word` fails; with the filter clause replaced
by `1 = 1`, the filter test fails. Both restored, 68 pass in
`server/agent/mail/`.

## Left to do

- **The Mail UI still shows its own chips**, not these five words. They display
  the same facts (category, urgency, needs-reply/action) in different language,
  so nothing is missing, but a person and the agent do not literally read the
  same word. Unifying them means sharing the derivation between `server/` and
  `apps/mail/web/`, which today would mean duplicating it — exactly the drift
  V4-27 just removed. Worth its own task.
- The tags are not published as IMAP keywords, so a phone does not see them:
  that is V4-33, deliberately separate because it writes to the real mailbox.
- No undo in the journal yet. Reversing a tag needs the previous category, which
  the result does not carry; the owner's "Wrong?" button is the undo path today,
  and it also locks the mail against the agent.
- Accuracy is unmeasured. CI tests the derivation and the write, with the `mock`
  provider — a mock cannot judge whether a mail really is `etudes`. Measuring
  that needs a labelled set and a real provider, outside CI.

  a small tax; want me to rename the category to `promo` everywhere instead?
- Tagging a mail the owner corrected is refused outright, even when the
  correction was only about "needs a reply" and the agent wants to add `etudes`.
  Simple and safe, slightly blunt. Narrow it to the plane that was corrected?
- Should an agent be allowed to tag `spam`? It is only a word today, but once
