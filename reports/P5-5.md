# P5-5: Assisted newsletter unsubscribe (List-Unsubscribe, confirmation)

- Branch: `night/P5-5` (on top of `night/P5-3`) · Instance: sodium-7a · Date: 2026-11-14
- Status: done

## Done

- **Mail reader**: on mail with a `List-Unsubscribe` header, the banner "This
  mail comes from a mailing list. Unsubscribe…" opens a confirmation dialog
  that says exactly what will happen:
  - **one-click** (RFC 8058) → Nextcloud Mail's own route
    `/api/list/unsubscribe/<id>`, then "Unsubscribed" in the reader;
  - a **web page** → opens in a new tab (`noopener`); the user finishes there;
  - a **mailto** → the composer opens with the address and subject; the user
    sends it.

  Only http(s) links are shown (`javascript:` and other schemes are ignored).
  The mail itself is not moved; the dialog points to Mail > Rules (P5-3).
- **PHP** `AtriumAgentController` (internal only), two new ops:
  - `listinfo`: link, one-click and mailto, read from the server;
  - `unsubscribe`: one-click POST. It refuses if the link is no longer the
    mail's link or not https. Nextcloud's HTTP client refuses local
    addresses.
- **Agent tools** `server/agent/unsubscribe/` (`unsubscribeModule()`, one line
  in `server/agent/index.ts`):
  - `mail_unsubscribe_info` (read): what the list offers, and advice for what
    only the owner can do;
  - `mail_unsubscribe` (action `send`, so **the owner's approval** by default):
    one-click only. The link is frozen in the approval; the approval is void
    if the link changed. Web pages and mailtos are never followed by an agent.

- **End to end** (port 8203):

  - the internal PHP route from outside → 403.
