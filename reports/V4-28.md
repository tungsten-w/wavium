# V4-28: classify the folders you pick, and catch up an old question set

## Done

Two things the audit of 2026-11-23 named (card 5): the pipeline only ever
looked at Inbox and Spam, and a change of `questions.json` version reclassified
nothing, so an account's history stayed on the old questions forever.

**The folders are a choice, per account.**

- `TriageService::folderChoice()` / `setClassifiedFolders()` (new), stored in
  app config `mail` → `triage_folders` as `{accountId: [mailboxId, ...]}`. An
  account with no entry keeps the old behaviour (Inbox + Spam), so nothing
  changes for an instance that never touches the setting. An entry with an
  empty list means "classify nothing from this account" and is kept as such.
- `setClassifiedFolders()` refuses an account that is not the caller's
  (`DoesNotExistException` → 404) and silently drops folder ids that are not
  that account's, rather than trusting them.
- `triageMailboxes()` applies the choice; the default rule lives in one place
  (`isDefaultFolderRow()`) and the status page reads it from there, so the page
  cannot disagree with the pipeline about which folders are classified.
- `PUT /apps/mail/api/triage/folders` (`triage#setFolders`, `NoAdminRequired`:
  these are the person's own folders).
- Mail status > Folders has a **Classify** box per folder. The UI sends the
  whole list for that account, so unticking the inbox is a real choice and not
  "nobody chose" (which would fall back to Inbox + Spam).

**A folder added later is picked up as backlog, not as new mail.** `enqueue()`
used one global cursor (`scannedUpTo` + `firstScanDone`) over the only two
folders it ever scanned. A folder chosen afterwards would either be missed (its
mail is older than the cursor) or, after a reset, pass for new mail and spend
today's budget for new mail in one go. Each folder now keeps its own cursor in
`triage_state.boxes` (`{upTo, done}`); a folder with no cursor is scanned from
its oldest mail with `priority 0`, which is the backlog lane with its own daily
€ cap. The first run of this code hands the old global cursor to Inbox and Spam,
once — the presence of the `boxes` key is the marker — so no instance rescans
its inbox. Folders dropped from the choice keep their cursor, so choosing one
again does not rescan it.

**Catching up an older question set.**

- `outdated()` counts the mail of this user's accounts whose `mail_triage.version`
  is not the current one, and prices it: the average of the last 100 real
  classifications, or an estimate from `bodyChars` when nothing was priced yet.
  It is in the status payload, so the page shows the cost *before* anything runs.
- Left out of the count and of the catch-up: mail the owner corrected by hand
  (`model = corrected-by-user`), which a catch-up must never overwrite, and mail
  already waiting in the queue.
- `requeueOutdated()` queues at most `max` of them (hard cap
  `BACKFILL_MAX = 500`), newest first, as `priority 0` with `attempts` reset —
  so the daily backlog cap decides how fast they are really redone, not the
  button. `POST /apps/mail/api/triage/backfill`.
- Mail status shows a **Catch up** card only when there is something to catch
  up: how many, which version, the estimated total, and "Redo 100 now".
- The parameter is `max`, not `limit`: the framework range-checks any controller
  parameter named `limit` against 1..500 and answers **500** when it is out of
  range, before the controller runs. Written up in `docs/lessons.md`.

Also: the reader line for an unclassified mail said "only Inbox and Spam are
classified automatically", which is no longer true; it now points at Mail
status › Folders.

## Left to do

- A mail an agent tagged (`model = tagged-by-agent`, V4-24) *is* redone by a
  catch-up: the tags are derived from the classification, so a newer question set
  re-deciding them is the point. Only a human correction is sacred. Worth
  revisiting if agent tags ever become facts of their own.
- The catch-up is one button for every account of the user. Per-account
  catch-up, and a "redo everything older than X" in the background, are not
  there.
- Choosing a folder that was never synced queues nothing until the folder has a
  local copy (the sync is what fills it). The page says "Not synced yet (opens
  on first visit)" in the same row, but the two facts are not tied together.
- No browser test: the Folders table and the Catch up card are covered by DOM
  tests, not by Playwright.
